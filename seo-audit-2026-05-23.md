### 2. All category pages missing Open Graph + Twitter Card tags
The 13 top-level category pages (homepage, culture, economy, education, environment, flora-fauna, geography, government, history, indigenous, technology, tourism, medical) have **zero** OG or Twitter tags. When shared on social media they will render with no image, no description, and a raw URL — significantly reducing click-through rates.

**Affected pages:** `/`, `/culture/`, `/economy/`, `/education/`, `/environment/`, `/flora-fauna/`, `/geography/`, `/government/`, `/history/`, `/indigenous/`, `/technology/`, `/tourism/`, `/medical/`, `/medical/dental/`

**Fix:** Add to each `<head>`:
```html
<meta property="og:title" content="[Page Title]">
<meta property="og:description" content="[Meta description]">
<meta property="og:url" content="https://australia.md/[path]/">
<meta property="og:type" content="website">
<meta property="og:image" content="https://australia.md/og-default.png">
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:title" content="[Page Title]">
<meta name="twitter:description" content="[Meta description]">
```

---

### 3. `og:image` missing from every single page
Even the dental suburb pages (which have other OG tags) are missing `og:image`. Social shares of any page will show no image preview on Twitter/X, Facebook, LinkedIn, WhatsApp.

**Fix:** Create one default social image at `https://australia.md/og-default.png` (1200×630px) and add `<meta property="og:image" content="https://australia.md/og-default.png">` to every page's `<head>`.

---

### 4. Category pages missing JSON-LD schema entirely
The 13 top-level pages have no structured data at all. These pages are your primary entry points and should signal their content type to Google.

**Fix:** Add a `WebPage` + `BreadcrumbList` block to each category page:
```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "WebPage",
      "@id": "https://australia.md/culture/",
      "name": "Culture & Arts | Australia.md",
      "url": "https://australia.md/culture/",
      "inLanguage": "en-AU",
      "isPartOf": { "@id": "https://australia.md/" }
    },
    {
      "@type": "BreadcrumbList",
      "itemListElement": [
        { "@type": "ListItem", "position": 1, "name": "Australia.md", "item": "https://australia.md/" },
        { "@type": "ListItem", "position": 2, "name": "Culture", "item": "https://australia.md/culture/" }
      ]
    }
  ]
}
</script>
```

### 7. Homepage missing JSON-LD Organisation + WebSite schema
The homepage (`/index.html`) has no structured data at all. This is where Google expects to find `Organization` and `WebSite` (with `SearchAction`) schema.

**Fix:**
```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "Organization",
      "@id": "https://australia.md/#org",
      "name": "Australia.md",
      "url": "https://australia.md/",
      "description": "Open-source sovereign knowledge base for Australia.",
      "sameAs": ["https://github.com/Australia-md/archive"]
    },
    {
      "@type": "WebSite",
      "@id": "https://australia.md/#website",
      "url": "https://australia.md/",
      "name": "Australia.md",
      "publisher": { "@id": "https://australia.md/#org" }
    }
  ]
}
</script>
```

---

### 8. Dental suburb pages use `MedicalWebPage` but not `Dentist` entity schema
Current schema describes the page (`MedicalWebPage`) but not the clinics themselves. Adding a `Dentist` block per clinic would enable rich results in Google (address, phone, hours in search snippets).

**Fix:** For each clinic in a suburb page, add inside the `@graph`:
```json
{
  "@type": "Dentist",
  "name": "Clinic Name",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "41-43 Market St",
    "addressLocality": "Balranald",
    "addressRegion": "NSW",
    "postalCode": "2715",
    "addressCountry": "AU"
  },
  "telephone": "(03) 5071 9808",
  "openingHoursSpecification": [...]
}
```
