## 3. Critical Issues Fixed (P0)

### 3.1 ✅ Sitemap contained 3 dead URLs (404s)
`sitemap.xml` listed pages that do not exist on disk (no HTML, no OKF doc). Submitting 404s in a sitemap erodes crawler trust and wastes crawl budget.

| Removed URL | Reason |
|---|---|
| `https://australia.md/medical/dental/balgownie/` | No page on disk |
| `https://australia.md/medical/dental/balmain/` | No page on disk |
| `https://australia.md/medical/dental/balranald/` | No page on disk |

**Fix:** Removed from `sitemap.xml`. *(If these suburbs are intended, create the pages and re-add.)*

### 3.2 ✅ 18 live pages missing from the sitemap
These dental suburb pages exist and are linked but were not discoverable via the sitemap:
`bangalow, bangor, bankstown, banora-point, barham, barrack-heights, bateau-bay, batehaven, batemans-bay, bathurst, baulkham-hills, beaconsfield, beaumont-hills, beecroft, bega, belfield, bella-vista, bellevue-hill`.

**Fix:** Added all 18 with `lastmod 2026-06-22`, `priority 0.6`, `changefreq monthly`.

### 3.3 ✅ 23 OKF documents missing from the sitemap
The `docs/**` OKF v0.1 bundle (raw Markdown, served via `.nojekyll`) was only half-listed. Missing entries included `docs/index.md`, `docs/medical/index.md`, `docs/medical/dental/index.md`, and 20 suburb docs.

**Fix:** Sitemap regenerated from disk so **all 53** `docs/*.md` are listed (`priority 0.4`). The full bundle is now consistently advertised to AI/search crawlers.

> **Result:** `sitemap.xml` now lists **107 URLs** (54 HTML + 53 Markdown), is well-formed XML, and has **0 dead links and 0 missing pages** (reconciled against disk).

## 4. High-Priority Issues Fixed (P1)

### 4.1 ✅ 21 pages missing `og:image` + `twitter:image`
20 older dental suburb pages and `submit/index.html` had partial social markup — when shared on X, Facebook, LinkedIn, WhatsApp, Slack, etc., they rendered with **no preview image**.

**Fix:** Added to each page, matching the format already used on newer pages:
```html
<meta property="og:image" content="https://australia.md/og-default.png" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta name="twitter:image" content="https://australia.md/og-default.png" />
```
Dental pages additionally received `twitter:title`/`twitter:description`. `submit/` was upgraded from `twitter:card="summary"` to `summary_large_image` (a 1200×630 asset is available). **All 54 pages now carry a complete OG + Twitter set.**

### 4.2 ✅ Wrong domain in `submit/` structured data
`submit/index.html` JSON-LD referenced **`https://australiamd.org/`** in 4 places (`url`, `isPartOf.url`, and two breadcrumb `item`s) while its canonical and Open Graph correctly used `https://australia.md/`. Conflicting URLs in structured data confuse entity resolution and can split signals.

**Fix:** All 4 occurrences corrected to `https://australia.md/`. *(Isolated to this one file — no other page was affected.)*

### 4.3 ✅ Stale `lastmod` dates
All sitemap entries were dated ≤ 2026-05-23 (most 2026-05-12), so genuinely updated pages would not be re-crawled promptly.

**Fix:** Pages substantively edited this session (the 21 OG pages + dental directory) and all newly added URLs are stamped `2026-06-22`; untouched pages retain their prior, accurate `lastmod` (avoids a misleading "everything changed today" signal).

## 5. Medium / Low Issues Fixed (P2–P3)

### 5.1 ✅ Broken Subresource Integrity hash on Google Fonts (33 pages)
33 dental pages loaded fonts via:
```html
<link href="https://fonts.googleapis.com/css2?…" rel="stylesheet"
      integrity="sha384-1PT8…" crossorigin="anonymous" />
```
The Google Fonts `css2` endpoint returns **different CSS per User-Agent** (to serve the right font format), so a fixed SRI hash fails verification in many browsers → the browser **blocks the stylesheet** → Space Grotesk/Inter silently fall back to system fonts. The other 21 pages already omit the hash and render correctly.

**Fix:** Stripped `integrity` + paired `crossorigin="anonymous"` from the `css2` `<link>` on all 33 pages (the `fonts.gstatic.com` preconnect `crossorigin` was preserved). All pages now load fonts consistently.

### 5.2 ✅ Dental directory `<title>` too short & inconsistent
`medical/dental/index.html` had `<title>Dental — NSW | Australia.md</title>` (27 chars) and a JSON-LD `name` of "Dental **Directory** — NSW", while its own `og:title`/`twitter:title` already said "Dental **Clinics Directory** — NSW". Three different titles on one page.

**Fix:** `<title>` and the `MedicalWebPage` `name` aligned to **"Dental Clinics Directory — NSW | Australia.md"** (45 chars, keyword-rich, consistent across `<title>`, OG, Twitter, and both JSON-LD blocks).

### 5.3 ✅ `lang` attribute imprecise (54 pages)
Every page declared `<html lang="en">` while its JSON-LD declared `inLanguage: "en-AU"`. For a country-specific archive, `en-AU` is the correct, more precise locale signal.

**Fix:** `lang="en"` → `lang="en-AU"` across all 54 pages, aligning the HTML lang with the structured-data locale.

### 5.4 ✅ No custom 404 page
GitHub Pages serves `/404.html` for unmatched URLs; none existed, so visitors and crawlers hit the default. Lost UX and link-recovery opportunity.

**Fix:** Added a branded, self-contained `404.html` (`noindex, follow`; inline CSS with the site's green/gold tokens; absolute-path navigation back to Home, Dental directory, and key categories). Self-contained so it renders correctly regardless of the depth of the missing URL.

## 7. Remaining Opportunities (Not Applied) 🟡

These are sound next steps but were intentionally **not** changed in this pass — they need product decisions or carry higher risk/effort:

1. **Self-host or `preload` fonts.** Google Fonts `<link rel="stylesheet">` is still render-blocking. `&display=swap` is already set (good); for best LCP, consider self-hosting woff2 or adding a `preload`. *(Performance, not correctness.)*
2. **`Dentist` schema completeness.** Most dental pages include `Dentist` + `PostalAddress`; some lack `openingHoursSpecification`/`telephone`. Populating these enables richer local-business snippets.
3. **`dateModified` in JSON-LD.** Some dental pages carry `dateModified: 2026-03-26` in structured data; align these with real edit dates for freshness signals.
4. **Decide whether raw `.md` belongs in the primary sitemap.** Raw Markdown won't produce rich results and mirrors the HTML pages (mild duplicate-content surface). Kept for now (consistent with the project's OKF/AI-crawler intent); consider a separate `sitemap-okf.xml` if you want to segregate machine-readable assets from indexable HTML.
5. **`FAQPage` schema on category pages.** History/Geography/Indigenous contain implicit Q&A that could be marked up for rich results.
6. **`hreflang`.** Single-locale site, so optional; a self-referencing `en-AU` + `x-default` is low priority.
